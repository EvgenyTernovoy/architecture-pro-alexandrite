### Cуществующие и потенциальные проблемные места

1. Единственный инстанс базы данных работает на запись и на чтение, в итоге база данных испытывает вывсокие нагрузки и увеличивается время отклика, не говоря уже о возможных потерях данных
2. Единственный инстанс RabitMQ. Если нагрузка сильно возросла возможы частые падения и перезагрузки из за нехватки ресурсов, что может привести к потери данных
3. Нет единой точки входа для приложения и API, в результате чего мы не можем контролировать трафик и настраивать rate limit.
4. MES имеет единственный инстанс. Это высоконагруженный сервис, который производит сложные расчеты. С ростом числа заказов увеличивается время обработки заказаов и возможны падения сервиса из за нехватки ресурсов.
5. Отсутствие монитроинга, логирования и трейсинга. В результате чего мы неможем выявить проблемные места
6. Отсутствие кеширования на частозапрашиваемых данных

### Инициативы, которые необходимы для устранения нежелательных ситуаций

1. Настройка мониторинга, логирования и трейсинга
2. Настройка шардирования и репликации баз даннных
3. Добавления серверного кеширования данных
4. Репликация MES сервиса в зависимости от нагурзки
5. Настройка API Gateway и ограничение трафика по API
6. Репликация RabitMQ, если выявим проблему связанную с нагрузкой


### Целевая арзитектурка через полгода

1. Настроен базовый мониторинг, для выявления проблемных мест
2. Настроено кеширование частозапрашиваемых данных
3. Настроена репликация и шардирования баз данных для снижениея нагрузки на каждый инстанс и повышения latency
4. Настроен API Gateway для контроля трафика
5. Настройка репликации MES системы для повышения скорости обработки заказов

### Если бы у вас была возможность выполнить только три пункта из списка инициатив в ближайшие полгода, что бы вы выбрали и почему?

1. Настроен базовый мониторинг, для выявления проблемных мест - без мониторинга сложно/невозможно выявить проблемные места и вовремя реагировать на инциденты
2. Масштабирование MES сервиса или баз данных - сейчас главная проблема, это потеря заказов. Нужно выявить проблемное место и масштабировать, возможно вертикально с помощью добавления ресурсов, как временная мера. В иделе настроить горизонтальное масштабирование
3. Настройка API Gateway и ограничение трафика по API - здесь мы должны контролировать трафик от партнеров, т.к партнеры могут непреднамеренно создавать высокую нагрузку на наш сервис. Плюс это позволит нам настроить трейсинг запросов
